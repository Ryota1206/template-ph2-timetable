# ユーザー認証機能 仕様書

## 1. 概要

既存のLaravel製時間割管理アプリに、以下の3つの機能を実装する。

- ユーザー登録機能
- ログイン機能
- ログアウト機能

また、時間割関連ページへのアクセスをログイン済みユーザーのみに制限する。

既存の時間割管理機能を維持し、認証機能に必要な範囲で実装すること。

## 2. ユーザー登録機能

### URL
`/register`

### 入力項目とバリデーション

| 項目 | 条件 | エラーメッセージ |
|---|---|---|
| 名前 | 必須 | 名前を入力してください |
| 名前 | 255文字以内 | 名前は255文字以内で入力してください |
| メールアドレス | 必須 | メールアドレスを入力してください |
| メールアドレス | メール形式 | メールの形式が違います。直してください |
| メールアドレス | 255文字以内 | メールアドレスは255文字以内で入力してください |
| メールアドレス | 登録済み不可 | このメールアドレスは既に登録済みです |
| パスワード | 必須 | パスワードを入力してください |
| パスワード | 8文字以上 | パスワードは８文字以上で入力してください |
| パスワード | 確認用と一致 | パスワードが違います |

### 動作

- 名前・メールアドレス・パスワード・確認用パスワードの4項目を表示する。
- パスワード確認用フィールドは `password_confirmation` とする。
- バリデーションエラーは、各入力欄の直下に表示する。
- バリデーションに失敗した場合は登録画面に戻る。
- エラー時は入力済みの名前とメールアドレスを保持する。
- パスワードと確認用パスワードは保持しない。
- 登録成功時はユーザーをデータベースに保存する。
- パスワードはLaravel標準のハッシュ化処理を利用して保存し、平文では保存しない。
- 登録成功後は自動的にログインする。
- 自動ログイン後は `/entries` にリダイレクトする。

## 3. ログイン機能

### URL
`/login`

### 入力項目

- メールアドレス
- パスワード

### 動作

- 登録済みのメールアドレスとパスワードで認証する。
- 認証に成功した場合は `/entries` にリダイレクトする。
- 認証に失敗した場合は `/login` に戻る。
- 認証失敗時は「メールアドレスかパスワードが違います」と表示する。
- 認証失敗時は入力済みのメールアドレスのみ保持する。
- パスワードは保持しない。
- 認証エラーはメールアドレス入力欄の下に表示する。
- Laravel標準のセッション認証を利用する。

## 4. ログアウト機能

### URL
`/logout`

### 動作

- ログイン済みユーザーがログアウト操作を行えるようにする。
- ログアウト処理にはPOSTリクエストを使用する。
- ログアウト時はLaravel標準の認証機能を用いて認証状態を解除する。
- セッションを無効化し、CSRFトークンを再生成する。
- ログアウト成功後は `/login` にリダイレクトする。
- ログアウト後は、再度ログインするまで時間割関連ページにアクセスできない。

## 5. アクセス制御

### 未ログインの場合

以下のページおよび処理は、すべてログイン必須とする。

- `/entries`（時間割一覧）
- `/entries/create`（時間割登録）
- `/entries/{id}`（時間割の編集・更新・削除など既存の処理）
- `/courses`（授業一覧）
- その他、既存の時間割関連のルート

未ログインでこれらにアクセスした場合は `/login` にリダイレクトする。

### ログイン済みの場合

- `/register` にアクセスした場合は `/entries` にリダイレクトする。
- `/login` にアクセスした場合は `/entries` にリダイレクトする。
- 時間割関連ページには通常どおりアクセスできる。
- 既存のユーザーごとのデータ管理と認可処理を維持する。

## 6. リダイレクト仕様

| 操作・状況 | リダイレクト先 |
|---|---|
| ユーザー登録成功 | `/entries` |
| ログイン成功 | `/entries` |
| ログイン失敗 | `/login` |
| ログアウト成功 | `/login` |
| 未ログインで時間割関連ページにアクセス | `/login` |
| ログイン済みで `/register` にアクセス | `/entries` |
| ログイン済みで `/login` にアクセス | `/entries` |
| ユーザー登録のバリデーション失敗 | `/register` |

## 7. 実装上の制約

- Laravel標準の認証機能を利用すること。
- パスワードは必ずハッシュ化して保存すること。
- ログイン成功時と登録後の自動ログイン時は、セッションIDを適切に再生成すること。
- CSRF対策を適用すること。
- 既存のUserモデルとusersテーブルを利用すること。
- 既存の時間割データ、ユーザーとの関連付け、Policyによる認可処理を維持すること。
- 既存の画面デザインを必要以上に変更しないこと。
- 認証機能とアクセス制御に関係のない機能は変更しないこと。
- メール認証、パスワード再設定、ソーシャルログインなど、仕様にない機能は追加しないこと。
- 仕様が不明確な部分は、勝手に推測せず確認すること。

## 8. 完了条件

以下をすべて満たした場合に実装完了とする。

- 新しいユーザーを登録できる。
- 登録時の各バリデーションが正しく動作し、指定した日本語メッセージが表示される。
- 登録成功後に自動ログインし、`/entries` が表示される。
- 登録済みユーザーがログインできる。
- ログイン失敗時に指定したエラーが表示され、メールアドレスが保持される。
- ログアウト後に `/login` が表示される。
- 未ログインでは時間割関連ページにアクセスできない。
- ログイン済みでは `/register` と `/login` から `/entries` にリダイレクトされる。
- 既存の時間割登録・一覧表示・削除機能が正常に動作する。
- 他のユーザーのデータに対する既存のアクセス制限が維持される。

### メールアドレスの大文字・小文字の扱い

- メールアドレスの大文字と小文字を区別する。
- `test@example.com` と `TEST@example.com` は異なるメールアドレスとして扱う。
- メールアドレスの登録時に、大文字・小文字を自動変換しない。
- 重複チェックでは、大文字・小文字まで完全に一致する場合のみ登録済みと判定する。
- ログイン時も大文字・小文字を区別し、登録されたメールアドレスと完全に一致する場合のみ認証を行う。
- データベース側でも大文字・小文字を区別できるようにする。
- 既存のユーザー情報やデータベース構造は、必要な範囲以外変更しない。
